# 04｜页面：API 投影

本文不是功能定义。功能只有模型和 API 两个要点；本文只记录页面如何投影 API 返回的模型、派生状态和所属 Pi transcript。

每个区域写明层级、信息来源、空/忙/错状态、响应式行为，以及用户动作对应的 API、等待反馈、成功更新和失败后保留的草稿。页面不定义新字段、新状态或新接口。

组件选择遵循 `01` 的 AI Elements 规则。没有合适官方组件时，先登记例外，再实现替代。

## 当前规则

## 1. 产品术语与页面分层
| 内部对象 | 页面名称 | 用户看到的作用 |
| --- | --- | --- |
| Bot | Bot | 有固定工作目录的协作管理对象 |
| Agent | Agent | 独立版本化 Markdown 角色；用途为协调或项目，关系只在 Bot 配置建立，见 `02`“Agent Markdown 与 Bot 绑定” |
| BotConversation | 总对话 | 持续交流入口，固定项目范围和协调 Agent 版本 |
| ProjectCall | 项目调用 | 一次对项目会话的调用；协调画布显示调用 ID、项目、状态，以及已完成调用的最终输出或读取错误 |
| Session.botConversationId | 所属协调会话 | 直接表达项目会话父归属，不另建绑定对象 |
| Project | 项目 | 文件与执行资源边界 |
| Session | 项目会话 | 可复用 Pi 上下文，多任务/多次工作共享原会话历史 |
| SessionMemory | 记忆 | Session 自动总结和人工干预的辅助工作线 |
| 无SessionMemory | SessionMemory 模板 | 可复制的初始上下文 |
| 其他资源模板/项目实例 | 模板库 / 项目资源 | 在 Project 内复制、配置与单独调试 |

前端保持 `Route → View → Feature Wrapper → AI Elements/基础组件` 分层。状态、同源 API 与 NDJSON 解析分别放在 Hook/API Client 中，页面 JSX 只装配可读区域。

## 2. 顶层导航与创建
~~~text
/
├─ 快捷操作：新建项目会话 / 记忆模板库
├─ Bot [＋]
│  ├─ 新建 Bot：配置调度角色、设置协作项目范围
│  └─ Bot
│     └─ 协调总对话
│        └─ 该总对话的项目 Session
├─ Project [＋ 新建项目]
│  └─ Project A
│     ├─ 点击项目行：进入最近项目会话并切换记录树展开状态
│     ├─ 展开箭头：只切换记录树
│     └─ 项目会话：可选项目角色和空 SessionMemory/记忆模板
│     └─ 独立 Session 记录：显示当前生效记忆摘要；独立空会话显示“新会话”；单击后进入该 Project Session，收起右侧面板、文件预览及所有浮窗。Bot 项目 Session 不在此重复显示
└─ 角色 / MCP / Settings
~~~

Agent 导航入口位于侧栏底部，产品文案为“角色”，显示规则见“Agent 列表弹窗与独立编辑工作区”。MCP 入口只管理资源；模板不能直接执行，复制后的配置和调试属于目标 Project。角色定义与绑定按 `02`“Agent Markdown 与 Bot 绑定”。

新建 Bot 表单一次配置调度 Agent 与项目集合；后续新建总对话直接开始并继承 Bot 配置。Bot 项目范围不预建 Project Session 或 SessionMemory。创建独立项目会话的弹窗仍显示 Project、可选的同项目角色、空 SessionMemory/模板选择与模板内容预览；不选角色也可创建并直接发送。角色入口联动见“Agent 列表弹窗与独立编辑工作区”。复制记忆模板只初始化新会话的指导线展示，不建立草稿、不影响主 Pi 请求。Project 新建/编辑和删除确认继续使用弹窗，不占用右侧检查列。

## 3. 主画布与列
桌面默认布局：

~~~text
Bot / Project Navigation | 当前总对话或项目对话 | Context Panel（按需）
~~~


Project 导航使用低亮度浅灰蓝背景，不出现“AI Workspace”顶部品牌栏，不使用深蓝背景或蓝色正文。项目、会话和操作文字采用中性灰黑；选中项使用柔和浅绿色背景和标记。蓝色只用于克制的焦点、图标和主要操作。主画布避免大面积刺眼纯白或高饱和浅蓝。

## 4. Session 对话
~~~text
ProjectSessionPage
├─ Header：Project / 当前 Session / 导航与 Context Panel 开关
├─ Conversation
│  └─ 用户 entry → assistant 文本 entry → 工具调用 entry
├─ SessionMemory 状态入口：指导线内容 / 同步状态
└─ Composer
~~~

Assistant 回复使用安全 Markdown，常见标题、段落、列表、引用、行内格式、代码块和表格可读；原始 HTML 不执行，链接协议需校验。项目会话和协调会话只按所属 Pi transcript 当前分支的可见 entry 时间顺序投影。可见 entry 只有用户消息、assistant 文本和工具调用。工具调用是独立 entry，不嵌入 assistant 消息，也不用自定义数据卡或改写后的工具标签渲染。页面不生成执行过程、模型轮次、第几轮或思考摘要。工具调用用原生 disclosure 默认收起，展开后只显示真实工具名、状态和安全目标。session、model、thinking、custom 等 entry 不显示。


项目会话及协调会话 Composer 的输入框下方紧邻并排提供“上传文件”和“参考项目文件”两个入口，已选文件在两个入口下方显示，与输入框边线保持间距，文件名长度不撑开入口间距。发送后的用户消息不标注文件。上传打开系统文件选择器，不关联项目；参考打开视口居中的可关闭模态对话框，项目会话展示所属项目，协调会话默认展示所属 Bot 工作目录，也可切换至已绑定的活动项目；逐级浏览目录、多选文件，不提供路径输入。两类选择均可移除，随消息提交；接受前失败保留输入和选择并显示错误。项目会话无可用项目时禁用参考入口；Bot 项目 Session 仍只读。

项目会话提交后运行期间，首个可见文本或工具活动到达前，在本地回显下显示带转圈的“正在思考”；首个可见内容到达、执行结束或失败后隐藏。这是等待响应提示，不是模型 thinking 内容或 transcript entry。

Composer 支持 Enter 发送、Shift+Enter 换行；发送按钮仍可直接提交。IME 候选组合期间按 Enter 只确认候选、不提交；判断同时使用 composition 事件状态、`nativeEvent.isComposing` 和旧浏览器 `keyCode=229` 兼容标记。此行为在独立 Project Session 与 Bot 总对话共用的 Composer 中一致。运行时发送/停止处于同一操作组。项目 Session 在排队、启动和运行阶段均可停止；提交停止后显示“正在停止”，保持执行门禁直到 Runtime 确认结束。结果 unknown 时不提供会伪装取消的停止按钮，显示待核对状态和准确恢复入口。Composer 不提供模型、Runtime、工具、Agent、MCP 或 Skill 的配置控件。

## 5. 固定指导线展示
记忆以工作概况、目标、项目约束、重要事实、决策、下一步、产出七个固定部分展示，含义以 `02`“SessionMemory 当前上下文”为准。面板保留名称“记忆”；顶部立即总结和同步状态保留，每部分正文旁小号“修改”打开富文本局部编辑。总结及人工修改只更新展示，不显示“用于下一条对话”或“已生效提示词”等标签。

## 6. 总结与校正反馈
每次完整回答后独立增量总结并直接展示；等待、错误、未知同步状态如实呈现。人工保存刷新原栏位及侧栏摘要，弹窗提示“仅修改总结展示；其他部分不变”。取消/关闭丢弃未保存修改并中止客户端请求，不操作主会话 Runtime。

## 7. 文件与检查
项目文件树从独立文件列表 API 加载，即使 Project 不是 Git 仓库也能浏览和预览。根目录按钮标为“项目根目录”，路径栏显示 Project.rootPath 与当前子目录组成的绝对路径，长路径允许横向滚动。Git 状态与变更为可选附加信息，失败时不得替代或隐藏文件列表。

文件预览只读，代码区域使用柔和浅灰绿底和深灰文字，不使用黑色背景。空目录、加载中、读取失败、目录截断和二进制/超限文件有明确状态。服务端执行路径越界、敏感段、符号链接和大小检查。SessionMemory 产出中的相对路径链接只有经同一安全校验后才可打开预览。

检查面板展示当前 Session 状态、Pi Runtime 恢复诊断、真实工具活动和项目资源的安全摘要；不显示 secret、原生 transcript 文件路径、Runtime 句柄或完整内部 system prompt。

## 8. 响应式、空状态与可访问性
| 场景 | 页面表现 | 可用操作 |
| --- | --- | --- |
| 没有 Project | 项目欢迎页 | 新建项目 |
| Project 没有 Session | 项目空状态 | 创建会话与空 SessionMemory，或选 SessionMemory 模板 |
| LLM 总结中或失败 | 独立进度/错误，不遮挡对话 | 继续对话、重试 |
| Session unavailable | 保留 transcript 与 SessionMemory 内容 | 恢复或诊断 |
| Project 被停用 | 历史内容只读 | 管理 Project |


## 9. 本版 UI 不包含
- 独立于 Bot 的旧跨项目会话、旧执行时间线和旧审查卡；Bot 新布局以“Bot 总对话与多 Session 协作页面”为准；
- Session 对话中展示 SessionMemory 自动总结作为 Pi 原始思考；
- SessionMemory context 文件、原生 JSONL、secret 或未脱敏工具输出；
- SessionMemory 内的工具、扩展、Agent、MCP、Skill 编辑入口；
- 用户可见的 SessionMemory 内容版本系统。

## 10. SessionMemory 面板操作细节
~~~text
记忆                     [立即总结] [关闭]

与已完成对话同步 · 更新时间
  工作概况                         修改
  目标 / 约束 / 事实 / 决策 / 下一步   各自修改
  产出摘要                         修改 / 安全文件链接
~~~

仅展示已保存的当前记忆及同步状态，不展示候选差异、草稿审核或确认入口。状态与恢复依据见 `03`“API 响应、状态与恢复”。

当前内容不设统一“编辑”按钮。七个栏位正文旁各有小号“修改”文字操作，无边框、底色和按钮留白，空值时与“尚未填写”并排显示；已填写时仍在内容区域提供同样入口。文字操作保留键盘可达性和清晰焦点。点击后用模态弹窗修改该部分，原面板保持展示。弹窗提供加粗、斜体、段落和列表的富文本编辑；数组支持逐条新增、删除和排序，产出保留标题与安全相对路径输入。富文本转换为安全 Markdown 字符串，不存 HTML、不增字段，容量与路径约束仍以 `02` 为准。局部修改基于打开弹窗时的完整上下文快照和 writeETag，只替换选中字段后条件保存；冲突不盲合并。弹窗固定最大高度，编辑区超长滚动。



## 11. 冲突、生成和恢复反馈
| 状态 | 页面说明 | 操作 |
| --- | --- | --- |
| queued / generating | “等待当前对话结束” / “正在整理会话上下文” | 继续对话；生成中不显示假的百分比 |
| 表单写入冲突 | “内容已更新，你的修改尚未保存” | 保留本地输入、加载最新内容对照、重新编辑提交 |
| 生成失败 | 安全错误及重试提示，当前生效内容仍可用 | 重试 |
| 来源过长 | “本次对话超过总结上限，未跳过来源” | 继续对话、手动维护当前内容、重试；不伪装已总结 |
| 来源不可用 | “无法读取对话来源，自动总结暂停” | 主 Session 恢复/诊断；当前内容仍可人工维护 |
| 数据损坏 / 旧库不兼容 | 明确损坏或兼容诊断 | 诊断入口；不能以空内容显示或继续关联写入 |



## 12. “立即总结”按钮与计数反馈
“立即总结”位于右侧面板最上方标题栏、关闭按钮左侧。内容区不重复显示记忆标题，不显示生效说明、自动触发规则或回答计数说明；只显示必要的生成状态、错误和操作结果。触发规则与计数仍以 `03`“每次回答增量同步”为准，行为不变。

| 场景 | 按钮行为与提示 |
| --- | --- |
| 有稳定新来源 | 可点击，与自动总结共用 LLM 流程，校验后直接更新 |
| 尚无可总结的对话 | 允许点击，原位提示“没有新对话可总结，请先完成一次回答”，不调用模型 |
| 主会话正在回答、有新来源 | 点击后排队，显示“将在当前回答结束后总结”；不停止主会话 |
| 正在生成 / 已排队 | 禁用并显示“正在总结” / “等待回答结束”，不重复建立任务 |
| 生成失败 | 保留错误并允许“重试总结”，与立即总结共用调度；不提供固定冷却等待 |
| Project 只读 / 来源不可恢复 | 禁用并显示对应原因 |




## 13. 检查面板：原生上下文

~~~text
原生上下文                      自动压缩已关闭
已用：32,000 / 128,000 Token     25%
剩余：96,000 Token
测量：原生指标 / 估算 / 暂不可用   更新时间
最近手动压缩：时间 / 尚无记录
[压缩原生上下文]
压缩会调用模型并消耗 Token，保留原生会话历史。
~~~

用量数值及比例配合低饱和进度条；比例超出容量时如实显示数值，图形可满格并标超限。接近容量（已知比例 ≥80%）显示提醒“可手动压缩以减少上下文占用”，达到或超出容量显示“上下文已满，请手动压缩后重新发送”；都不能自动执行。容量未知隐藏比例条并说明“模型容量未知”；无可靠用量显示“暂不可用”，不能显示空白或 0%。最后可信值显式标“上次测量”，运行中不伪装实时 Token 仪表。


压缩中 Composer 保留输入并提示暂不能发送；用户不需要重新打开会话。页面刷新或重新进入检查仅读取状态，不自动触发/重试压缩。检查不展示原生 transcript 路径、完整提示词、原始压缩摘要或秘密内容。

当前实现的模板创建/编辑随新建项目会话弹窗提供，独立 SessionMemory 模板库导航已接入。SessionMemory 支持指定连续来源范围重审，需在分支恢复验收中复验该入口。


记忆与检查采用相同的栏位间距、标题字号和细分隔线。摘要、目标、约束、事实、决策、下一步、产出分别展示，空栏位有明确文字；内容作用标记置于栏位内的辅助说明，不拼接在可展开标题上。“记忆 / 文件 / 检查”入口为三个分开的按钮，没有共享底色或连体外框。

“立即总结”禁用时通过按钮悬停说明原因：正在同步、先恢复会话或项目只读；编辑中则提示先保存或取消修改。不提供冷却倒计时，历史草稿不阻塞。

记忆局部修改弹窗中的富文本编辑区固定高 180px，超长内容在区内纵向滚动。已保存文本、列表及产出区域最高 160px，超过后在各自栏位内滚动，弹窗中的多条列表/产出控件区域最高 55vh，面板仍可整体滚动。取消请求不能撤销已完成的服务端事务；再次打开显示已保存事实，不用旧请求结果重新打开编辑或覆盖当前页面。

侧栏会话名称只使用当前记忆摘要，空白摘要回退为“新会话”，不使用 purpose、编号或历史草稿。摘要换行折为单行，长文本省略并可通过悬停查看完整名称；保存或 LLM 更新摘要后同步。

右侧面板高度限制在可视区域内，标题栏固定且不参与压缩；内容区占用剩余高度独立滚动。记忆、检查和文件内容区预留 8px 滚动条空间，使用浅灰绿轨道和清晰滑块，长内容不得从面板底部被裁切。

窄屏浮动右侧面板使用明确高度 `calc(100dvh - 24px)`（640px 以下减 16px），不依赖 auto 高度或内容撑开，关闭垂直居中定位。内容区占据标题栏之外的剩余空间；即使使用零 flex-basis，面板也不得缩为内容最小高度。

点击左侧会话时，关闭记忆/文件/检查面板、文件预览、记忆局部修改弹窗、项目资料弹窗、会话创建弹窗、SessionMemory 模板库和旧 SessionMemory 创建弹窗。未保存的记忆局部修改自动取消，不阻止会话切换。

项目行进入最近会话、直接点击会话记录，以及会话 ID 实际切换，均调用同一套关闭逻辑：关闭右侧面板及浮窗，不将已打开面板重置成检查视图。关闭的右侧面板从页面卸载；只有用户再次点击记忆、文件或检查才显示。

已有 SessionMemory 数据保留。应用启动不自动改写数据库，也不恢复旧实体或旧协议。

## 14. 检查中优先显示 Pi 上下文
检查内容顺序为“Pi 上下文 → Session → 运行环境 → 资源安全摘要”。Pi 区使用现有检查栏位样式，展示执行状态、已用/容量/剩余 Token、占比、采样时间、测量口径、最近压缩时间及“手动压缩”策略。状态与操作集中，按钮为刷新、压缩上下文；压缩运行时显示取消压缩，禁用不适用操作并给出原因。不显示任何原生上下文完整正文。

未启动显示“发送首条消息后可管理”，不可恢复显示恢复会话入口，取消显示“压缩已取消”，失败保留错误并允许用户重试。刷新失败标明未能取得最新状态，不将旧用量伪装当前。未知指标以文字呈现；占比已知时使用安全范围的进度条与实际数值。修改工作记忆继续在记忆面板，管理模型窗口和压缩集中在检查的 Pi 区。


## 15. 实时记忆同步与纠错展示
记忆作为与主对话并行的纠错线，标题栏的立即总结保留，正文顶部仅用简短状态行显示“与已完成对话同步 / 正在同步记忆 / N 条回答待同步 / 同步失败 / 来源不可用”，显示最近更新时间；不显示自动触发规则和回答计数说明。每次回答后后台更新直接写当前记忆，无需确认。

打开面板、主请求开始/结束和人工保存后立即刷新，全会话共享状态读取：同步中每 2 秒，已同步且面板可见每 30 秒，面板关闭且已同步时停止轮询，页面隐藏暂停，重新可见立即读取；摘要名称随写入同步，面板关闭时主会话仍读取安全同步摘要。富文本弹窗输入保持用户本地修改，不被轮询覆盖；冲突时保留输入并显示错误。人工修正立即更新指导线展示和后续独立总结，即使 LLM 同步尚未完成也不进入主请求。状态显示只保证跟随已完成来源，不把 LLM 更新耗时隐藏为“实时完成”。

工具调用按所在 transcript entry 的时间位置显示，不挂到 assistant 消息下方。失败明确标出失败，不由相邻 assistant 文本掩盖。实时更新按事件到达顺序追加，不重排已显示的历史 entry，也不补造轮次。

## 16. Bot 总对话与多 Session 协作页面（当前目标）
本节只投影 `03`“协调会话 API”。协调会话和项目 Session 是不同对象；页面不把它们合并成同一段对话，也不发明另一套状态。

### 16.1 导航与主入口

左侧 Bot 树固定 Bot→协调总对话→该总对话的项目 Session 三层。Bot 项目 Session 只在父协调会话下显示，不在 Project 树重复列出；独立 Project Session 保留在 Project 树。一个 WorkspaceSelection 只高亮一个当前对象，展开不抢选中。

~~~text
左侧                     协调总对话主画布                    右侧按需
Bot / 协调总对话         总对话标题、Project 范围             项目范围与 Agent 职责
  / 项目 Session         用户需求与协调回复                   项目调用状态
                         [协调 Session | anpm 项目 Session | ...]
                         当前标签对应的真实 Pi transcript
                         项目调用 ID、状态和有界进度
                         输入框（只发送到协调 Session）
~~~

Bot 树中的项目 Session 是同一会话的导航入口。顶部项目标签显示该 Session 的真实 Pi transcript 和调用状态，第三层导航进入同一 Pi 历史。Composer 只属于协调标签，不携带目标项目 Session。独立 Project Session 仍按当前记忆摘要命名，空摘要显示“新会话”。切换时关闭预览和浮窗，输入草稿保留，已保存的项目调用继续。

每条开放的协调会话行提供危险样式的“删除协调会话”按钮。点击后先确认：这会直接删除该协调会话及其关联项目 Session、独有记忆和 Pi 历史，不可恢复，不是归档。会话尚未结束时直接强制删除，不等待其结束；失败时保留原页并就地显示错误。成功后从常用树移除，若当前选中该会话或其项目 Session，回到所属 Bot。

### 16.2 Bot 配置与总对话创建

Bot 创建/设置选择协调 Agent、可协作 Project 集合和每项目一个 Agent；项目知识来自绑定版本 Agent.md，参考文件生成材料不当作绑定。Project 选择搜索只用于配置 Bot 的范围，不代表协调会话获得 Project 文件访问权；名称/路径在窄屏可读，配套明确主要/次要/危险按钮。

新协调会话直接开始，继承 Bot 配置，不预建项目 Session、SessionMemory 或项目调用。它可以连续接收多个需求。每次项目调用按调用 ID 显示状态，不用一个总进度代替各次调用。

### 16.3 项目范围与项目调用

页面显示当前协调会话的项目范围、项目名称和绑定 Agent 名称。它不把 Agent 定义显示成已经验证的代码事实。Bot 工作目录与 Project 根目录重叠时，常规文件预览依照其 API 显示访问拒绝；本轮显式参考可浏览并选择 Bot 工作目录中的文件。

每次项目调用显示调用 ID、项目名称和状态。同一项目 Session 的多次调用按调用 ID 分开。`accepted` 显示尚未开始，不显示成失败。

### 16.4 工作进度与结果

项目调用只显示 `02` 定义的 `accepted`、`working`、`completed`、`aborted` 或 `unknown`。页面不把这些状态改写成另一套阶段，也不把工具结束显示成调用完成。

协调画布与项目会话画布只显示同一类可见 entry：用户输入、assistant 文本和默认收起的工具调用，按 Pi transcript 当前分支的时间顺序依次显示。工具调用不嵌入 assistant 消息，不使用自定义数据格式。不显示执行过程或第几轮。协调画布不再使用项目 Session 标签栏。每次已发起的项目调用额外显示一张默认收起的项目输出卡片；没有调用就不显示空卡片。

`completed` 卡片显示该次 assistant 原文；原文为空或边界无法读取时显示错误，不显示成成功结果。`accepted` 显示尚未开始，`working` 显示处理中，`aborted` 显示已中止，`unknown` 显示结果未知。这些状态都不把缺失原文伪装成有效输出。卡片可独立展开，不把项目原文混入协调输出。Composer 只属于协调会话。

运行公开文本和安全工具活动只在所属 Session transcript 尾部更新。私有 thinking、原始参数、未脱敏结果和绝对路径不下发。`completed` 的项目原文保留在项目 Session；`aborted` 和 `unknown` 不显示成有效结果。协调会话在项目调用未完成时仍可接收用户输入，新的项目事实仍必须通过项目工具取得。

项目或协调会话提交后立即清空 Composer，并在对话中显示本地回显；运行不等待模型结束才清空。发送失败时仅在对应会话草稿未被修改的情况下恢复原文，不覆盖其他会话或新输入；流已接受后的错误以事件和 transcript 为准，不自动重发。用户提交协调消息后，页面立即显示该输入和“正在等待协调会话响应”，不等待首个模型事件。202 接受后保持处理中；首个文本或工具事件到达后改显示实时内容。收到完成事件后立即恢复 Composer，历史刷新在后台进行，不延长输入禁用。transcript 已包含这次输入后，只保留这一条，不再同时显示本地回显。`SESSION_BUSY` 和其他发送失败只在 Composer 显示错误，保留输入草稿，不产生未处理异常。

### 16.5 用户介入

页面不提供暂停调度、停止工作或向项目 Session 直接发送的入口。用户修正只输入协调 Session，由协调会话决定是否调用修正工具。`unknown` 显示待核对，并只提供“放弃该调用”；放弃后才允许同一项目 Session 接受新写入。控制失败就地显示，不能覆盖协调 transcript。

### 16.6 故障与恢复操作

恢复项按目标 Session 显示在同一画布：哪次项目调用边界未知、哪个 Project、Agent 或原生历史不可用，以及对应动作。协调项位于协调标签，项目项位于准确项目标签。切换标签同时切换 transcript、调用状态和恢复操作。`unknown` 只能核对或明确放弃，不能显示成已完成或已失败。预算预检在 Pi 输入前拒绝且没有原生开始证据时，在原协调 Session 显示“输入未送达”、原用户文本和预算原因，并提供“重新处理原输入”；不清除文本，也不复制成新的协调输入。

按钮只来自协调会话 API 返回的操作许可。项目调用进行中不锁定协调 Composer。项目标签不提供独立 Composer，也不把项目 Session 的忙闲显示成协调会话不可输入。

右侧检查面板只提供角色、Bot 与对话配置。项目调用的核对和放弃只在所属项目 Session 标签中处理。检查面板不复制调用清单，也不提供第二个操作入口。

服务重载后按已保存调用和 Pi 边界重建事实，不伪造流式文本，也不自动重放用户输入。

### 16.7 Agent.md 诊断与版本采用

定义疑点在当前协调会话显示 Project、Agent、当前绑定版本、证据和影响。用户选择“查看并修改”或“暂不修改”。修改进入 Agent 编辑工作区，预填问题但不自动生成或保存；能力仍由用户单独设置。

保存新版本后，可以独立选择哪些同 Agent 的协调会话或项目 Session 采用新版。页面展示正文和能力差异，并说明只影响下一次项目调用。存在未完成或 `unknown` 调用时不能采用。Bot 默认采用必须提示“仅影响新协调会话”。

### 16.8 面板与可访问性

总对话保持项目/文件/检查；项目 Session 保持记忆/文件/检查。文件根分别 Bot 工作目录和 Project.rootPath；记忆只供独立总结与校正，无 Bot Memory。检查显示原生容量未知/估算及运行来源，压缩仍手动。

可操作按钮区分主要/次要/危险、禁用有具体理由，恢复卡通过键盘可访问。长任务/Session/历史列表分页或内部滚动，不撑大主画布；窄屏纵向/可关闭面板可读。前端组件接入遵守 `01`“AI Elements 组件治理”，文档设计不代表已完成官方选型或前端验收。

## 17. Agent 列表弹窗与独立编辑工作区
点击侧栏 Agent 后先弹出角色列表，不把列表塞进右侧检查面板，也不离开当前主会话。弹窗顶端固定“新增 Agent”；列表行展示 Agent 名称、协调/项目用途、最新版本和状态，操作为“修改”“删除”。关闭列表回到原页面与原 Composer 草稿。

角色列表的“新增 Agent”为主要按钮；行内“修改/停用/恢复”为次要描边按钮，“删除”为危险描边按钮。Agent 编辑页的“保存 Agent/保存新版本”和“发送意见”为主要按钮，“返回列表/取消”为次要描边按钮；行内低频查看入口可保留文字操作。

角色选择器的“新增 Agent/修改”、版本区的配置/采用/查看动作、项目 Agent 单选下拉框的“完成”，以及编辑过程中的转换/取消请求操作，都使用统一按钮样式；移除文件标签和关闭弹窗等纯图标动作保持紧凑图标按钮。主要、次要、危险按钮共用 `ui-button` 样式层级，避免看起来像普通文本。

桌面端角色列表弹窗在视口内居中并保留安全边距；列表有紧凑标题区、明确的新增操作、可滚动角色行和居中的空状态，角色用途/版本/状态以短标签分组展示。Agent 编辑工作区不是弹窗：它占据左侧导航以外的主画布与右侧列，隐藏当前会话画布/检查面板但不改变其选择或草稿；中间为意见对话，右侧为只读 Markdown。用途与参考材料归入紧凑配置区，对话历史占可伸缩区域，意见输入固定在对话底部，Markdown 空态提供生成指引，底部取消/保存始终可见。小屏下工作区在应用主视图内纵向滚动，将对话与预览堆叠显示，不压缩成难读的窄双栏。

点“新增 Agent”或某行“修改”后，列表弹窗收起，进入应用主视图的独立编辑工作区，而不是再开一层弹窗。工作区占中间主画布和右侧列：中央为 Agent 专用意见对话，右侧为只读规范 Markdown 展示/差异；左侧导航保持可见。它不复用当前 Pi 会话，不显示项目会话消息，不新增到当前对话树。

~~~text
新建 Agent · 协调角色                                  关闭

参考 Project [搜索并选择……]     参考文件 [上传文件]
（仅供生成/修订，不会绑定到 Agent 或 Bot）

AI：我从材料中整理出以下职责……               v1 / 草稿差异
用户：希望增加跨项目配置对比，保留权限边界……   ---
AI：已补充比较步骤，边界保持不变。              name: ...
                                                description: ...
[补充修改意见……                    发送]        ## 工作方式
                                                ……
状态/错误/取消生成

取消编辑                                          保存新版本
~~~

Agent 用途在创建时明确选择；编辑/新建都不选 Bot 或 Project 归属。参考 Project 可按名称/路径搜索，参考文件可上传；两者均作为本次 LLM 的材料来源，并显示为“仅供生成/修订”。材料不会作为 Agent 的访问权限、工作目录或 Bot 绑定。新建 Bot 可保存为“待配置”状态；在选择协调 Agent 前禁用“新建总对话”。

所有上传 Markdown 都显示 LLM 识别状态，再进入候选工作稿。中央意见输入支持多轮自然语言修改；每次得到有效候选后，右侧显示当前保存版本/草稿、变更摘要及差异。用户不能手动编辑 Markdown 正文；能力权限使用独立显式开关、默认关闭，不由 LLM 自动开启。生成失败/取消保留最近有效草稿。

编辑器“取消”关闭工作区、丢弃本次未保存草稿/意见/候选并返回 Agent 列表弹窗，数据库和已保存 Markdown 不变。“保存新版本”创建不可变 Markdown 版本与目录索引记录，成功后返回列表刷新当前版本。已被 Bot/Session 引用时删除按钮改为解释性归档操作，保留历史文件；无引用时可确认删除。

### 17.1 新建 Bot 的 Agent/Project 绑定

Bot 配置中的“采用角色最新版（仅影响新总对话）”明确刷新表单提交的协调与项目 Agent 版本；相同选择也采用新版本，普通保存则保留旧版。默认版本更新后新总对话继承新版；已有总对话/项目 Session 可按“持续会话显式采用提示”独立明确安全采用，不在执行中热更新。

Agent 目录是独立角色库。新建 Bot 表单只显示一个协调 Agent 字段标题；选择 0..N 个 Project，并在每个 Project 的分组下通过可搜索单选下拉框选择 0 或 1 个项目 Agent。项目搜索或 Agent 搜索都不清除已有选择。此处才保存 coordinator-Bot、Project-Bot 和 Project-Agent-Bot 关系。项目 Agent 按该 Bot 的配置关系提供候选，不从 Agent 生成所用的参考 Project 推断。Bot 设置复用相同的项目 Agent 单选下拉框。

Bot 会话直接继承 Bot 当前协调 Agent、Project 范围和项目 Agent 版本快照；后续会话不重复弹选择器，既有总对话不受 Bot 配置修改影响。独立项目 Session 从 Agent 目录选择项目 Agent。Project Directory 只读感知范围内的 Project/Agent，不依赖 `readProjects`，也不读取项目源文件；需要项目操作时必须派发到存在且能力合适的项目 Session。历史 `readProjects` 不再授权协调者直接检索。

Agent 列表与创建/修改工作区是独立浮层状态。关闭编辑器返回列表；关闭列表返回之前对话。不得因打开或关闭 Agent 弹窗清空主 Composer、切换会话、取消后台任务或污染对话历史。

### 17.2 持续会话显式采用提示

编辑器产生不可变 Agent 版本，保存和取消仍独立。从协调会话进入编辑后，返回原来的选择和输入。采用条件与历史保护只引用 `02`“Agent Markdown 与 Bot 绑定”和 `03`“持续 Session 的同角色新版采用”。未采用的项目 Session 继续显示原绑定版本，不能因目录刷新显示成已经升级。
