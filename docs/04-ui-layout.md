# 04｜UI 布局

> 状态：**单项目 SessionMemory 目标 UI，核心面板与入口已实现，完整响应式验收待复验。** 本轮只设计 Project Session、绑定 SessionMemory 和模板选择；跨项目页面以后另行设计。既有项目对话、文件浏览和视觉约束继续保留。

## 1. 产品术语与页面分层

| 内部对象 | 页面名称 | 用户看到的作用 |
| --- | --- | --- |
| Project | 项目 | 文件与执行资源边界 |
| Session | 项目会话 | Pi 原生对话与执行工作线 |
| SessionMemory | 记忆 | Session 自动总结和人工干预的辅助工作线 |
| 无SessionMemory | SessionMemory 模板 | 可复制的初始上下文 |
| 其他资源模板/项目实例 | 模板库 / 项目资源 | 在 Project 内复制、配置与单独调试 |

前端保持 `Route → View → Feature Wrapper → AI Elements/基础组件` 分层。状态、同源 API 与 NDJSON 解析分别放在 Hook/API Client 中，页面 JSX 只装配可读区域。

## 2. 顶层导航与创建

~~~text
/
├─ Project 列表
│  └─ Project A
│     ├─ 点击项目行：进入最近项目会话并切换记录树展开状态
│     ├─ 展开箭头：只切换记录树
│     ├─ 新建项目会话：选择空 SessionMemory 或 SessionMemory 模板
│     └─ Session 记录：显示当前生效记忆摘要；摘要为空显示“新会话”；单击后进入该 Session，收起右侧面板、文件预览及所有浮窗
├─ 新建项目会话：先选择 Project
├─ 模板库
└─ Agent / MCP / Settings
~~~

Agent 与 MCP 导航入口仍可位于侧栏底部；打开时默认只展示当前 Project 的独立实例。项目为空的资源只在模板库出现，模板页提供“复制到项目”，复制后的配置和调试状态在项目内维护。具体资源编辑页待其基础模型定义。

创建项目会话的弹窗先显示 Project、空 SessionMemory/模板选择与模板内容预览。复制模板只初始化新会话的指导线展示，不建立草稿、不影响主 Pi 请求。Project 新建/编辑和删除确认继续使用弹窗，不占用右侧检查列。

## 3. 主画布与列

桌面默认布局：

~~~text
Project Navigation | Session 对话主画布 | Context Panel（按需）
~~~


Project 导航使用低亮度浅灰蓝背景，不出现“AI Workspace”顶部品牌栏，不使用深蓝背景或蓝色正文。项目、会话和操作文字采用中性灰黑；选中项使用柔和浅绿色背景和标记。蓝色只用于克制的焦点、图标和主要操作。主画布避免大面积刺眼纯白或高饱和浅蓝。

## 4. Session 对话

~~~text
ProjectSessionPage
├─ Header：Project / 当前 Session / 导航与 Context Panel 开关
├─ Conversation
│  └─ 用户消息 → Pi 实际模型轮次 → Assistant 输出
├─ SessionMemory 状态入口：指导线内容 / 同步状态
└─ Composer
~~~

Assistant 回复使用安全 Markdown，常见标题、段落、列表、引用、行内格式、代码块和表格可读；原始 HTML 不执行，链接协议需校验。Pi 模型轮次按真实 `turn_start/turn_end` 分组展示公开高层摘要和真实工具调用，每个请求先显示默认收起的“执行过程”总览（状态、轮次数、工具总数），展开后才能看到默认收起的轮次详情，可由鼠标或键盘独立展开。标题保留轮次、状态和工具数量；工具按调用顺序显示真实名称、运行状态和安全项目相对目标。没有公开摘要时如实显示未提供；不展示原始 thinking 或伪造流程。


Composer 支持 Enter 发送、Shift+Enter 换行，IME 输入中 Enter 不发送；运行时发送/停止处于同一操作组。Composer 不提供模型、Runtime、工具、Agent、MCP 或 Skill 的配置控件。

## 5. 固定指导线展示

记忆以工作概况、目标、项目约束、重要事实、决策、下一步、产出七个固定部分展示，含义以 `02` 第 3 节为准。面板保留名称“记忆”；顶部立即总结和同步状态保留，每部分正文旁小号“修改”打开富文本局部编辑。总结及人工修改只更新展示，不显示“用于下一条对话”或“已生效提示词”等标签。

## 6. 总结与校正反馈

每次完整回答后独立增量总结并直接展示；等待、错误、未知同步状态如实呈现。人工保存刷新原栏位及侧栏摘要，弹窗提示“仅修改总结展示；其他部分不变”。取消/关闭丢弃未保存修改并中止客户端请求，不操作主会话 Runtime。

## 7. 文件与检查

项目文件树从独立文件列表 API 加载，即使 Project 不是 Git 仓库也能浏览和预览。根目录按钮标为“项目根目录”，路径栏显示 Project.rootPath 与当前子目录组成的绝对路径，长路径允许横向滚动。Git 状态与变更为可选附加信息，失败时不得替代或隐藏文件列表。

文件预览只读，代码区域使用柔和浅灰绿底和深灰文字，不使用黑色背景。空目录、加载中、读取失败、目录截断和二进制/超限文件有明确状态。服务端执行路径越界、敏感段、符号链接和大小检查。SessionMemory 产出中的相对路径链接只有经同一安全校验后才可打开预览。

检查面板展示当前 Session 状态、Pi Runtime 恢复诊断、真实工具活动和项目资源的安全摘要；不显示 secret、原生 transcript 文件路径、Runtime 句柄或完整内部 system prompt。

## 8. 响应式、空状态与可访问性

| 场景 | 页面表现 | 可用操作 |
| --- | --- | --- |
| 没有 Project | 项目欢迎页 | 新建项目 |
| Project 没有 Session | 项目空状态 | 创建会话与空 SessionMemory，或选 SessionMemory 模板 |
| LLM 总结中或失败 | 独立进度/错误，不遮挡对话 | 继续对话、重试 |
| Session unavailable | 保留 transcript 与 SessionMemory 内容 | 恢复或诊断 |
| Project 被停用 | 历史内容只读 | 管理 Project |


## 9. 本版 UI 不包含

- 跨项目会话 总览、跨项目编排器/跨项目任务/旧执行记录 时间线或跨项目审查卡；
- Session 对话中展示 SessionMemory 自动总结作为 Pi 原始思考；
- SessionMemory context 文件、原生 JSONL、secret 或未脱敏工具输出；
- SessionMemory 内的工具、扩展、Agent、MCP、Skill 编辑入口；
- 用户可见的 SessionMemory 内容版本系统。

## 10. SessionMemory 面板操作细节

~~~text
记忆                     [立即总结] [关闭]

当前内容                          [编辑]
  当前摘要 / 目标 / 约束 / 事实 / 决策 / 下一步
  产出：仅展示                      [安全文件链接]

  来源 / 生成时间 / 已处理对话范围 / Token
  最新当前内容 ←→ 候选内容差异
  有新对话等待总结
~~~

差异按固定字段分组：字符串展示原文和候选；数组按条目展示新增、删除、保留及顺序变化；产出展示标题、摘要和安全路径差异。缺少原始生成快照时不伪造“模型改了什么”，显示最新当前内容与已存候选之间的差异。显示的来源范围、状态与恢复依据见 `03` 第 11 节。

当前内容不设统一“编辑”按钮。七个栏位正文旁各有小号“修改”文字操作，无边框、底色和按钮留白，空值时与“尚未填写”并排显示；已填写时仍在内容区域提供同样入口。文字操作保留键盘可达性和清晰焦点。点击后用模态弹窗修改该部分，原面板保持展示。弹窗提供加粗、斜体、段落和列表的富文本编辑；数组支持逐条新增、删除和排序，产出保留标题与安全相对路径输入。富文本转换为安全 Markdown 字符串，不存 HTML、不增字段，容量与路径约束仍以 `02` 为准。局部修改基于打开弹窗时的完整上下文快照和 writeETag，只替换选中字段后条件保存；冲突不盲合并。弹窗固定最大高度，编辑区超长滚动。



## 11. 冲突、生成和恢复反馈

| 状态 | 页面说明 | 操作 |
| --- | --- | --- |
| queued / generating | “等待当前对话结束” / “正在整理会话上下文” | 继续对话；生成中不显示假的百分比 |
| 表单写入冲突 | “内容已更新，你的修改尚未保存” | 保留本地输入、加载最新内容对照、重新编辑提交 |
| 生成失败 | 安全错误及重试提示，当前生效内容仍可用 | 重试 |
| 来源过长 | “本次对话超过总结上限，未跳过来源” | 继续对话、手动维护当前内容、重试；不伪装已总结 |
| 来源不可用 | “无法读取对话来源，自动总结暂停” | 主 Session 恢复/诊断；当前内容仍可人工维护 |
| 数据损坏 / 旧库不兼容 | 明确损坏或兼容诊断 | 诊断入口；不能以空内容显示或继续关联写入 |



## 12. “立即总结”按钮与计数反馈

“立即总结”位于右侧面板最上方标题栏、关闭按钮左侧。内容区不重复显示记忆标题，不显示生效说明、自动触发规则或回答计数说明；只显示必要的生成状态、错误和操作结果。触发规则与计数仍以 `03` 第 5.1 节为准，行为不变。

| 场景 | 按钮行为与提示 |
| --- | --- |
| 有稳定新来源、尚未达到自动阈值 | 可点击，提前生成历史待处理草稿；不自动确认 |
| 尚无可总结的对话 | 允许点击，原位提示“没有新对话可总结，请先完成一次回答”，不调用模型 |
| 主会话正在回答、有新来源 | 点击后排队，显示“将在当前回答结束后总结”；不停止主会话 |
| 正在生成 / 已排队 | 禁用并显示“正在总结” / “等待回答结束”，不重复建立任务 |
| 生成失败 | 保留错误并允许“重试总结”，与立即总结共用调度；不提供固定冷却等待 |
| Project 只读 / 来源不可恢复 | 禁用并显示对应原因 |




## 13. 检查面板：原生上下文


~~~text
原生上下文                      自动压缩已关闭
已用：32,000 / 128,000 Token     25%
剩余：96,000 Token
测量：原生指标 / 估算 / 暂不可用   更新时间
最近手动压缩：时间 / 尚无记录
[压缩原生上下文]
压缩会调用模型并消耗 Token，保留原生会话历史。
~~~

用量数值及比例配合低饱和进度条；比例超出容量时如实显示数值，图形可满格并标超限。接近容量（已知比例 ≥80%）显示提醒“可手动压缩以减少上下文占用”，达到或超出容量显示“上下文已满，请手动压缩后重新发送”；都不能自动执行。容量未知隐藏比例条并说明“模型容量未知”；无可靠用量显示“暂不可用”，不能显示空白或 0%。最后可信值显式标“上次测量”，运行中不伪装实时 Token 仪表。


压缩中 Composer 保留输入并提示暂不能发送；用户不需要重新打开会话。页面刷新或重新进入检查仅读取状态，不自动触发/重试压缩。检查不展示原生 transcript 路径、完整提示词、原始压缩摘要或秘密内容。

当前实现的模板创建/编辑随新建项目会话弹窗提供，独立 SessionMemory 模板库导航已接入。SessionMemory 支持指定连续来源范围重审，需在分支恢复验收中复验该入口。


记忆与检查采用相同的栏位间距、标题字号和细分隔线。摘要、目标、约束、事实、决策、下一步、产出分别展示，空栏位有明确文字；内容作用标记置于栏位内的辅助说明，不拼接在可展开标题上。“记忆 / 文件 / 检查”入口为三个分开的按钮，没有共享底色或连体外框。

“立即总结”禁用时通过按钮悬停说明原因：正在同步、先恢复会话或项目只读；编辑中则提示先保存或取消修改。不提供冷却倒计时，历史草稿不阻塞。

记忆局部修改弹窗中的富文本编辑区固定高 180px，超长内容在区内纵向滚动。已保存文本、列表及产出区域最高 160px，超过后在各自栏位内滚动，弹窗中的多条列表/产出控件区域最高 55vh，面板仍可整体滚动。取消请求不能撤销已完成的服务端事务；再次打开显示已保存事实，不用旧请求结果重新打开编辑或覆盖当前页面。

侧栏会话名称只使用当前生效记忆摘要，空白摘要回退为“新会话”，不使用 purpose、编号或历史待处理草稿。摘要换行折为单行，长文本省略并可通过悬停查看完整名称；保存摘要或确认草稿后更新。

右侧面板高度限制在可视区域内，标题栏固定且不参与压缩；内容区占用剩余高度独立滚动。记忆、检查和文件内容区预留 8px 滚动条空间，使用浅灰绿轨道和清晰滑块，长内容不得从面板底部被裁切。

窄屏浮动右侧面板使用明确高度 `calc(100dvh - 24px)`（640px 以下减 16px），不依赖 auto 高度或内容撑开，关闭垂直居中定位。内容区占据标题栏之外的剩余空间；即使使用零 flex-basis，面板也不得缩为内容最小高度。

点击左侧会话时，关闭记忆/文件/检查面板、文件预览、记忆局部修改弹窗、项目资料弹窗、会话创建弹窗、SessionMemory 模板库和旧 SessionMemory 创建弹窗。未保存的记忆局部修改自动取消，不阻止会话切换。

项目行进入最近会话、直接点击会话记录，以及会话 ID 实际切换，均调用同一套关闭逻辑：关闭右侧面板及浮窗，不将已打开面板重置成检查视图。关闭的右侧面板从页面卸载；只有用户再次点击记忆、文件或检查才显示。

本次统一清理：业务模型、API 和目标数据库只使用 SessionMemory/sessionMemory/session_memory_id/session_memories 命名，删除旧跨项目执行代码与协议；跨项目会话只保留无提交能力的页面入口，后续流程等待用户定义。已有数据库须离线按独立改名脚本迁移，保持 ID、JSON、原生会话引用和历史归档完整；应用启动不自动改写。

## 总结直接生效（2026-09-30）


历史 draftJson 仅保留旧数据，不再作为待办、不阻塞总结、不自动采用、不删除。新总结不创建 draftJson，模板复制直接初始化 contextJson。移除草稿编辑、确认、拒绝入口；手动总结使用 POST memory/summarize。页面只展示当前记忆、生成状态及局部修改，保存和自动更新后同步侧栏摘要。


## 14. 检查中优先显示 Pi 上下文

检查内容顺序为“Pi 上下文 → Session → 运行环境 → 资源安全摘要”。Pi 区使用现有检查栏位样式，展示执行状态、已用/容量/剩余 Token、占比、采样时间、测量口径、最近压缩时间及“手动压缩”策略。状态与操作集中，按钮为刷新、压缩上下文；压缩运行时显示取消压缩，禁用不适用操作并给出原因。不显示任何原生上下文完整正文。

未启动显示“发送首条消息后可管理”，不可恢复显示恢复会话入口，取消显示“压缩已取消”，失败保留错误并允许用户重试。刷新失败标明未能取得最新状态，不将旧用量伪装当前。未知指标以文字呈现；占比已知时使用安全范围的进度条与实际数值。修改工作记忆继续在记忆面板，管理模型窗口和压缩集中在检查的 Pi 区。


## 15. 实时记忆同步与纠错展示

记忆作为与主对话并行的纠错线，标题栏的立即总结保留，正文顶部仅用简短状态行显示“与已完成对话同步 / 正在同步记忆 / N 条回答待同步 / 同步失败 / 来源不可用”，显示最近更新时间；不显示自动触发规则和回答计数说明。每次回答后后台更新直接写当前记忆，无需确认。

打开面板、主请求开始/结束和人工保存后立即刷新，全会话共享状态读取：同步中每 2 秒，已同步且面板可见每 30 秒，面板关闭且已同步时停止轮询，页面隐藏暂停，重新可见立即读取；摘要名称随写入同步，面板关闭时主会话仍读取安全同步摘要。富文本弹窗输入保持用户本地修改，不被轮询覆盖；冲突时保留输入并显示错误。人工修正立即更新指导线展示和后续独立总结，即使 LLM 同步尚未完成也不进入主请求。状态显示只保证跟随已完成来源，不把 LLM 更新耗时隐藏为“实时完成”。

轮次列表在执行总览内最高 320px 并内部滚动，历史和实时均采用相同层级。运行时总览显示当前轮次和工具数；失败明确标出失败，不由最后思考状态掩盖工具错误。所有实际轮次仍能展开，回复始终展示在活动总览之后，不丢失历史记录。
