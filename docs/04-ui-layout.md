# 04｜UI 布局

> 状态：**单项目 Room 目标 UI，尚未按本版实现。** 本轮只设计 Project Session、绑定 Room 和模板选择；跨项目页面以后另行设计。既有项目对话、文件浏览和视觉约束继续保留。

## 1. 产品术语与页面分层

| 内部对象 | 页面名称 | 用户看到的作用 |
| --- | --- | --- |
| Project | 项目 | 文件与执行资源边界 |
| Session | 项目会话 | Pi 原生对话与执行工作线 |
| 项目 Room | 会话上下文 | 当前生效内容和一份待确认草稿 |
| 无项目 Room | Room 模板 | 可复制的初始上下文 |
| 其他资源模板/项目实例 | 模板库 / 项目资源 | 在 Project 内复制、配置与单独调试 |

前端保持 `Route → View → Feature Wrapper → AI Elements/基础组件` 分层。状态、同源 API 与 NDJSON 解析分别放在 Hook/API Client 中，页面 JSX 只装配可读区域。

## 2. 顶层导航与创建

~~~text
/
├─ Project 列表
│  └─ Project A
│     ├─ 点击项目行：进入最近项目会话并切换记录树展开状态
│     ├─ 展开箭头：只切换记录树
│     ├─ 新建项目会话：选择空 Room 或 Room 模板
│     └─ Session 记录：选择后进入该 Session 及绑定 Room
├─ 新建项目会话：先选择 Project
├─ 模板库
└─ Agent / MCP / Settings
~~~

Agent 与 MCP 导航入口仍可位于侧栏底部；打开时默认只展示当前 Project 的独立实例。项目为空的资源只在模板库出现，模板页提供“复制到项目”，复制后的配置和调试状态在项目内维护。具体资源编辑页待其基础模型定义。

创建项目会话的弹窗先显示 Project、空 Room/模板选择与模板内容预览。复制模板时明确提示哪些初始文字会形成待确认草稿；进入新 Session 后由用户确认是否用于后续对话。Project 新建/编辑和删除确认继续使用弹窗，不占用右侧检查列。

## 3. 主画布与列

桌面默认布局：

~~~text
Project Navigation | Session 对话主画布 | Context Panel（按需）
~~~

Context Panel 包含“Room”“文件”“检查”视图，三者在同一右侧列切换。选中文件时在主画布与右侧列之间插入文件预览列，右侧列保持打开并可继续切换文件/检查。Session 顶栏左侧的项目导航按钮可完全收缩左列；右上角的 Context Panel 按钮可收起或展开右列，收缩后主画布占满可用空间。切换面板不改变当前 Project、Session、草稿或正在运行的请求。

Project 导航使用低亮度浅灰蓝背景，不出现“AI Workspace”顶部品牌栏，不使用深蓝背景或蓝色正文。项目、会话和操作文字采用中性灰黑；选中项使用柔和浅绿色背景和标记。蓝色只用于克制的焦点、图标和主要操作。主画布避免大面积刺眼纯白或高饱和浅蓝。

## 4. Session 对话

~~~text
ProjectSessionPage
├─ Header：Project / 当前 Session / 导航与 Context Panel 开关
├─ Conversation
│  └─ 用户消息 → Pi 实际模型轮次 → Assistant 输出
├─ Room 状态入口：当前内容 / 待确认草稿数量
└─ Composer
~~~

Assistant 回复使用安全 Markdown，常见标题、段落、列表、引用、行内格式、代码块和表格可读；原始 HTML 不执行，链接协议需校验。Pi 模型轮次按真实 `turn_start/turn_end` 分组展示公开高层摘要和真实工具调用，所有轮次默认收起，可由鼠标或键盘独立展开。标题保留轮次、状态和工具数量；工具按调用顺序显示真实名称、运行状态和安全项目相对目标。没有公开摘要时如实显示未提供；不展示原始 thinking 或伪造流程。

发送用户消息时立即在画布中显示其文本和运行状态，等待服务端事件继续更新；流式输出、活动和消息变动后主内容区滚动跟随最新内容。Room 自动总结是独立的后续过程，其草稿状态显示在 Room 面板，不混入模型本轮分析或最终回答。

Composer 支持 Enter 发送、Shift+Enter 换行，IME 输入中 Enter 不发送；运行时发送/停止处于同一操作组。Composer 不提供模型、Runtime、工具、Agent、MCP 或 Skill 的配置控件。

## 5. Room 当前内容与生效位置

Room 面板上半区显示数据库中已确认的 `contextJson`。按“当前摘要、目标、项目约束、重要事实、决策、下一步、产出”固定顺序分组。摘要、目标、约束、事实、决策和下一步标记“下一条对话的提示词”；产出标记“仅展示”。每组可展开、编辑；用户保存当前内容就是确认，下一次用户提交读取最新内容。面板清楚注明修改不会改变已经发给 Pi 的当前请求。

项目 Room 不展示工具选择、扩展、Agent、MCP 或 Skill 设置，也不把模板库中的对象暗中注入 Session。Room 可以显示“复制自模板”的只读来源信息；模板后续修改不会自动同步。

## 6. Room 草稿与人工审查

Room 面板下半区显示 `draftJson`。生成中可显示进度；生成完成后展示来源（模板/规则/LLM）、新增对话范围、可获得的 Token 用量，以及与当前上下文的差异。用户可先编辑草稿，再点“确认用于后续对话”或“拒绝”。确认前始终标注“未生效”，不得让草稿出现在下一轮提示词。确认后立刻更新当前内容区；用户下一次发送消息时生效。

一个 Room 只有一份待确认草稿。草稿待处理期间有新对话时，页面提示“有新对话等待总结”，但不覆盖当前草稿。确认或拒绝后再处理这些对话。失败状态提供重试；模板复制、规则无变化和用户主动编辑都有明确反馈。不展示用户可见的内容版本或版本切换器。

## 7. 文件与检查

项目文件树从独立文件列表 API 加载，即使 Project 不是 Git 仓库也能浏览和预览。根目录按钮标为“项目根目录”，路径栏显示 Project.rootPath 与当前子目录组成的绝对路径，长路径允许横向滚动。Git 状态与变更为可选附加信息，失败时不得替代或隐藏文件列表。

文件预览只读，代码区域使用柔和浅灰绿底和深灰文字，不使用黑色背景。空目录、加载中、读取失败、目录截断和二进制/超限文件有明确状态。服务端执行路径越界、敏感段、符号链接和大小检查。Room 产出中的相对路径链接只有经同一安全校验后才可打开预览。

检查面板展示当前 Session 状态、Pi Runtime 恢复诊断、真实工具活动和项目资源的安全摘要；不显示 secret、原生 transcript 文件路径、Runtime 句柄或完整内部 system prompt。

## 8. 响应式、空状态与可访问性

| 场景 | 页面表现 | 可用操作 |
| --- | --- | --- |
| 没有 Project | 项目欢迎页 | 新建项目 |
| Project 没有 Session | 项目空状态 | 创建会话与空 Room，或选 Room 模板 |
| Room 当前内容为空 | 对话正常，Room 面板说明上下文为空 | 手动填写或等待自动草稿 |
| 模板草稿待确认 | Room 面板明确标记未生效 | 编辑、确认、拒绝 |
| LLM 总结中或失败 | 独立进度/错误，不遮挡对话 | 继续对话、重试 |
| Session unavailable | 保留 transcript 与 Room 内容 | 恢复或诊断 |
| Project 被停用 | 历史内容只读 | 管理 Project |

窄屏中 Project 导航和 Context Panel 转为可关闭的面板，当前对话及 Composer 优先可见，不遮挡流式内容或丢失草稿。按钮、折叠面板、表单和确认操作具备可访问名称、键盘操作、可见焦点和文字状态；`prefers-reduced-motion` 关闭非必要动画。

## 9. 本版 UI 不包含

- 跨项目 Room 总览、Router/Task/RoomRun 时间线或跨项目审查卡；
- Session 对话中展示 Room 自动总结作为 Pi 原始思考；
- Room context 文件、原生 JSONL、secret 或未脱敏工具输出；
- 未确认草稿的隐式生效；
- Room 内的工具、扩展、Agent、MCP、Skill 编辑入口；
- 用户可见的 Room 内容版本系统。
